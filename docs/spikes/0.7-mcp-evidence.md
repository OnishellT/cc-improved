# Spike 0.7: `PostToolUse` de `mcp__*` trae el texto del ticket

**Veredicto: PASA**, con dos salvedades que `lib/evidence.ts` debe tratar (ver "Contrato"):
`structuredContent` sustituye a los bloques de texto, y las respuestas grandes llegan como un aviso con la ruta de un archivo, no como el texto.

- Claude Code 2.1.309, `claude -p --model haiku` (`claude-haiku-5-5`), Node 22.23.2, 2026-10-23.
- Coste real: $0.0636 reportado por `total_cost_usd` en 19 sesiones (incluye la depuración del script y una pasada final completa de `run.sh`, que costó unos $0.026). El subagente de la ejecución C corre en segundo plano y su uso (~4k tokens de haiku) no aparece en ese `total_cost_usd`.

## Cómo se probó

`docs/spikes/0.7-mcp-evidence/run.sh <carpeta-vacía>` (reproducible; necesita `claude`, `node` y `jq`):

- `ticket-server.mjs`: servidor MCP stdio propio, sin dependencias ni red ni credenciales (JSON-RPC por líneas a mano). Nombre de servidor `lab-tickets`. Herramientas: `get_ticket` (un bloque de texto), `get_ticket_two_blocks` (dos bloques), `get_ticket_mixed` (texto + imagen PNG 1x1), `get_ticket_structured` (dos bloques + `structuredContent` con `outputSchema`), `get_ticket_error` (`isError: true`), `get_ticket_big` (texto de `chars` caracteres).
- `dump-hook.mjs`: hook que añade el stdin crudo a un `.jsonl`. Registrado en `PreToolUse`, `PostToolUse` y `PostToolUseFailure` con `matcher: "mcp__.*"`, y en `SubagentStart`/`SubagentStop`.
- Aislamiento: `--strict-mcp-config --mcp-config <solo lab-tickets>` y `--setting-sources project --settings <hooks>`: no participa ningún conector personal ni hook de usuario. El `init` de cada sesión lista un único servidor MCP: `{"name":"lab-tickets","status":"connected","source":"dynamic"}`.
- Ejecuciones: A (sesión principal, las cinco herramientas pequeñas), B (`get_ticket_big` de 20.000 caracteres con `MAX_MCP_OUTPUT_TOKENS=2000`), C (un subagente definido con `--agents` llama a `get_ticket`), S10000…S120000 (`get_ticket_big` con el límite por defecto).

Payloads reales recortados (rutas sustituidas por `<work-dir>` y `~/.claude/projects/<project>/`; sin credenciales ni datos de terceros) en `docs/spikes/0.7-mcp-evidence/payloads/`.

## Resultados

| Caso | Evento | `typeof tool_response` | Dónde está el texto |
|---|---|---|---|
| Un bloque de texto | `PostToolUse` | `array` | `tool_response[0].text` |
| Dos bloques de texto | `PostToolUse` | `array` | `tool_response[i].text` para cada `type: "text"`, en orden |
| Texto + imagen | `PostToolUse` | `array` | `[text, {type:"image", source:{type:"base64", media_type, data}}, {type:"text", text:"[Image: source: <ruta .png>]"}]`: Claude Code añade el tercer bloque |
| `structuredContent` (+ dos bloques de texto) | `PostToolUse` | `string` | `JSON.stringify(structuredContent)`. **Los bloques de texto no llegan** ni al hook ni al modelo (el transcript muestra lo mismo) |
| `isError: true` | `PostToolUseFailure` (no `PostToolUse`) | campo ausente | `error` (string) = texto del bloque; además `is_interrupt: false` |
| ≤ 50.000 caracteres, límite por defecto | `PostToolUse` | `array` | Completo en `tool_response[0].text` (50.000 caracteres verificados, marcador final incluido) |
| 60.000 y 120.000 caracteres, límite por defecto | `PostToolUse` | `string` | Aviso `Error: result (N characters across M lines) exceeds maximum allowed tokens. Output has been saved to <ruta>.txt.` + instrucciones. El texto completo está en ese archivo |
| 20.000 caracteres con `MAX_MCP_OUTPUT_TOKENS=2000` | `PostToolUse` | `string` | Igual que la fila anterior |
| Dentro de un subagente | `PostToolUse` | `array` | Igual que en la sesión principal; además `agent_id` y `agent_type` |

Otras observaciones:

- **Nombre observado:** `mcp__lab-tickets__get_ticket`, es decir `mcp__<clave del servidor en la config>__<nombre de la herramienta>`; el guion del nombre del servidor se conserva.
- **Campo `mcp_server`:** `PreToolUse`, `PostToolUse` y `PostToolUseFailure` de herramientas MCP traen `"mcp_server": {"name": "lab-tickets", "source": "dynamic"}`. `source: "dynamic"` corresponde a `--mcp-config`; otros valores (`.mcp.json`, usuario, conectores de claude.ai) no se observaron.
- **Claves de `PostToolUse` MCP (sesión principal):** `session_id, transcript_path, cwd, prompt_id, permission_mode, effort, hook_event_name, tool_name, tool_input, tool_response, tool_use_id, duration_ms, mcp_server`. En un subagente se añaden `agent_id` y `agent_type`.
- **Subagente:** `session_id` y `transcript_path` son los de la sesión **padre**; lo distingue `agent_id`/`agent_type` (`ticket-reader`). `SubagentStart`/`SubagentStop` llevan el mismo `agent_id`.
- **Archivo de salida grande:** `<dirname(transcript_path)>/<session_id>/tool-results/mcp-<server>-<tool>-<timestamp>.txt`, texto plano con el contenido íntegro (se comprobó el marcador final). La imagen va a la misma carpeta como `mcp-<server>-blob-<timestamp>-<sufijo>.png`.
- **Umbral por defecto:** entre 50.000 (en línea) y 60.000 caracteres (a archivo). No se buscó el valor exacto. El texto del aviso varía según el tamaño (a 120.000 añade una nota sobre líneas largas).
- **Matcher:** `"mcp__.*"` filtró correctamente: ni `ToolSearch` (que el modelo usó para cargar las herramientas MCP, diferidas) ni `Agent` aparecen en el log.
- **Tamaño del stdin del hook:** ~1 KB para un ticket corto; crece con el texto (50.851 bytes para 50.000 caracteres) y vuelve a ~2,4 KB cuando la salida va a archivo.

## Contrato para `lib/evidence.ts` (issue 16) y el hook de sesión (issue 21)

Entrada: el stdin de `PostToolUse` con `tool_name` que empieza por `mcp__`. Texto de evidencia:

1. `Array.isArray(tool_response)` → concatenar `b.text` de los bloques con `b.type === "text"`, en orden, separados por `\n`. Ignorar `image` y, si se quiere, el bloque sintético que empieza por `[Image: source: `.
2. `typeof tool_response === "string"`:
   - si casa con (probado contra los payloads de 20.000, 60.000 y 120.000 caracteres) `/^Error: result \(.*\) exceeds maximum allowed tokens\. Output has been saved to (.+?)\.\n/` → el texto es el contenido del archivo del grupo 1 (ruta absoluta). Es formato interno de Claude Code: si no casa o el archivo no existe, guardar el string tal cual y registrar el caso, nunca lanzar.
   - si no → el string tal cual (en la práctica, `structuredContent` serializado; los nombres del ticket siguen ahí si el servidor los incluye en el objeto).
3. `PostToolUseFailure` no es evidencia (el texto de error está en `error`).

Clave de almacenamiento: `session_id` (en subagentes es el del padre, así que la evidencia capturada por un subagente queda en la tarea del orquestador); `agent_id` opcional para saber quién la leyó. Origen: `tool_name` y `mcp_server.name`.

## Qué quedó sin comprobar

- Conectores reales (Claude Docs, Gmail, Drive…): no se usaron por regla del spike. Su nombre en este entorno sigue el patrón `mcp__claude_ai_<Conector>__<herramienta>` (visto en la lista de herramientas, no en un hook), y no se sabe si devuelven `structuredContent`, que cambiaría la forma.
- Servidores HTTP/SSE y `.mcp.json` del proyecto (solo stdio vía `--mcp-config`); otros valores de `mcp_server.source`.
- Salida grande dentro de un subagente: dónde se guarda el archivo (`transcript_path` del hook es el del padre).
- Tipos de bloque `resource`, `resource_link` y `audio`.
- Sesión interactiva: todo fue `claude -p`; no se espera diferencia en el payload del hook, pero no se vio.
- El umbral exacto por defecto y su relación con `MAX_MCP_OUTPUT_TOKENS`.

# Spike 0.1: `PreToolUse` de `ExitPlanMode`

Issue #3. Fecha: 2026-10-23. Claude Code **2.1.309**. Modelo pedido: `--model haiku` (ver "Modelo y coste").

## Veredicto: PASA (en headless con host SDK; la TUI interactiva no se ejecutó)

- El hook `PreToolUse` con matcher de `ExitPlanMode` recibe `tool_input.plan` (el Markdown completo) y `tool_input.planFilePath` (ruta absoluta en `~/.claude/plans/`). Visto en las dos llamadas de las dos ejecuciones.
- `permissionDecision: "deny"` con `permissionDecisionReason` vuelve al modelo como `tool_result` con `is_error: true`. El modelo editó el archivo de plan siguiendo la razón y volvió a llamar a `ExitPlanMode`. En la segunda llamada `tool_input.plan` ya traía el plan corregido.
- No hace falta el fallback (`PostToolUse` de `Write` sobre `~/.claude/plans/*.md`). Aun así ese evento también se observó: el `Write` del plan llega con `file_path` y `content`.

## Qué se comprobó y qué no

| Comprobación | Resultado | Cómo |
|---|---|---|
| `plan` y `planFilePath` en `PreToolUse` | **Visto** | variante `sdk-host`, 2 ejecuciones |
| La razón del `deny` llega al modelo | **Visto** (texto literal abajo) | `tool_result` en el stream y `permission_denials` del resultado |
| El modelo reescribe el plan | **Visto**: `Edit` sobre el archivo de plan y nueva llamada | ídem |
| Payload de `PermissionRequest` y `PostToolUse` de `ExitPlanMode` | **Visto** | ídem |
| Lo mismo en la TUI interactiva, con la persona aprobando en el diálogo | **No comprobado** | el spike no podía usar sesiones interactivas |

Por qué el resultado debería valer también en interactivo: el orden observado es `PreToolUse` → `PermissionRequest` → petición de permiso al host (`can_use_tool`, con `requires_user_interaction: true`) → `PostToolUse`. El hook decide antes de que nadie apruebe. En la TUI cambia solo quien contesta la petición de permiso (la persona en vez del host). Es una inferencia, no una observación.

## Por qué falló en `-p` y cómo se llegó al host SDK

El laboratorio anterior anotó que "en `-p` con haiku el tool quedó deferido". Lo observado ahora es otra cosa: en `-p` sin manejador de permisos, `ExitPlanMode` **no existe** en la sesión. No está deferido:

| Variante | Flags relevantes | Herramientas en la sesión | Resultado |
|---|---|---|---|
| `plan-default` | `--permission-mode plan` | sin `ExitPlanMode`; `ToolSearch select:ExitPlanMode` → `{"matches":[],"total_deferred_tools":19}` | el modelo responde que `ExitPlanMode` "is disabled in this session" |
| `plan-tools` | + `--tools "Read,Write,Edit,Glob,Grep,ExitPlanMode"` | sin `ExitPlanMode` aunque se nombró | ídem |
| `stream-json` | + `--input-format/--output-format stream-json` | `system/init.tools` = `["Edit","Glob","Grep","Read","Write"]` | ídem |
| **`sdk-host`** | + `--permission-prompt-tool stdio` y un host que contesta `can_use_tool` | `system/init.tools` = `["Edit","ExitPlanMode","Glob","Grep","Read","Write"]` | **`ExitPlanMode` llamado dos veces, denegado y aprobado** |

`--permission-prompt-tool stdio` es lo que usa el Agent SDK cuando el host pasa `canUseTool`. El host del script (`host.mjs`, unas 30 líneas de Node) aprueba todo lo que se le pide. En las dos ejecuciones solo se le pidió `ExitPlanMode`.

## Consecuencias para el plan de cc-improved

1. **El validador del plan va en `PreToolUse` de `ExitPlanMode`.** Lee `tool_input.plan` directamente. No hace falta leer `planFilePath`, aunque está disponible.
2. **`PostToolUse` de `ExitPlanMode` es distinto.** `tool_input` llega vacío y el plan está en `tool_response.plan`. La ruta viene como `tool_response.filePath`, no como `planFilePath`. `permission_mode` ya es `"default"`. El hook que marca `status: implementing` debe leer esos campos.
3. **La razón llega con el prefijo `PreToolUse:ExitPlanMode hook error: `.** Debe entenderse sola. No puede depender de que el modelo vea un formato concreto.
4. **Corrección al riesgo "Plan mode en `-p` no expone `ExitPlanMode`" (plan, sección 4).** No es que esté deferido. En `-p` el tool no existe salvo que haya un manejador de permisos (`--permission-prompt-tool stdio`, que es lo que pone el Agent SDK con `canUseTool`). Para la eval headless (fase 3) hay entonces una alternativa a `acceptEdits` + `PostToolUse(Write)`: un host SDK mínimo como `host.mjs`, que ejercita el mismo gate de plan mode que usa la persona.
5. **El plan file no se puede redirigir.** Se probó `plansDirectory` (ruta absoluta en `--settings`) y se ignoró en 2.1.309. Los planes acaban en `~/.claude/plans/` con nombres aleatorios (`plan-how-to-add-<adj>-<noun>.md`). El fallback, si algún día hiciera falta, debería emparejar por `session_id`, no por nombre.

Una pista sin verificar: el binario 2.1.309 describe `plan` como "The plan content (injected by normalizeToolInput from disk)" y `planFilePath` como "The plan file path (injected by normalizeToolInput)". Eso sugiere que Claude Code rellena ambos campos desde el archivo antes de los hooks, aunque el modelo no los pase. El stream de salida ya muestra el input normalizado, así que este spike no puede distinguir los dos casos.

## Modelo y coste

Con `--model haiku`, `system/init.model` es `claude-haiku-5-5`, pero en plan mode casi todo el gasto se factura a `claude-sonnet-5-5`. En la ejecución 1 de `sdk-host`: sonnet $0.0707, haiku $0.0029. Comprobación aislada con `--tools ""` y el prompt "Reply: ok": sin plan mode solo aparece `claude-haiku-5-5` ($0.0007); con `--permission-mode plan` solo aparece `claude-sonnet-5-5` ($0.019). La causa no se investigó. Importa para la fase 3: "modelo barato + plan mode" no fue barato aquí.

## Reproducir

```bash
docs/spikes/0.1-exit-plan-mode.sh <dir-desechable> sdk-host        # solo la variante que pasa (~$0.05-0.08)
docs/spikes/0.1-exit-plan-mode.sh <dir-desechable>                 # las cuatro variantes (~$0.25)
```

El script crea en `<dir>/<variante>/` un repo de juguete (`a.js`), el hook (`hook.sh`, que vuelca stdin y deniega el primer `ExitPlanMode`), un `settings.json` que se pasa por `--settings` y, para `sdk-host`, `host.mjs`. Ejecuta `claude -p --model haiku --permission-mode plan --max-budget-usd 0.15`. Deja `hooks.log`, `result.json[l]`, `host.log` e imprime un resumen. Requiere `claude`, `jq`, `git` y `node`. Cada ejecución deja un `plan-*.md` en `~/.claude/plans/`.

Las tres primeras variantes se ejecutaron con una versión anterior del script que además pasaba `plansDirectory` en `settings.json`. El ajuste se quitó porque no tenía efecto; el resto es igual.

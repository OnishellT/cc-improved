# Spike 0.2: hook tipo `agent` en `PreToolUse` con modelo fuerte

Issue: #4. Fecha: 2026-10-23. Claude Code 2.1.309, headless (`claude -p`).

## Veredicto

**PASA** con matcher `Write`. Con un veredicto negativo, el hook `agent` (`model: "opus"`, `timeout: 240`) bloquea la herramienta, y el modelo principal recibe la razón literal y la corrige. Coste del hook por invocación: entre $0.027 y $0.040, por debajo del tope de $0.30. No se activa la opción B del issue #19.

Salvedad para #19: el matcher `ExitPlanMode` no se pudo probar en headless (ver "Qué no quedó comprobado"). Esa parte depende del spike 0.1 (#3).

## Qué se probó

`docs/spikes/0.2-agent-hook.sh <dir-vacío>` crea un proyecto desechable con:

- `a.js` (una función `add`).
- `.checker/plan-rules.md` con dos reglas: el plan lleva una línea `Risk: low|high` y nombra cada archivo que cambia. Al modelo principal no se le dice que existe ese archivo, así que solo el hook puede conocer la regla, y solo leyéndolo.
- `.claude/settings.json` con un `PreToolUse` de matcher `Write` que lleva dos hooks: el `agent` y un `command` que registra la marca de tiempo (corre en paralelo). Hay además un `PostToolUse` de `Write` con ese mismo `command`.

Hook agent (literal):

```json
{ "type": "agent", "model": "opus", "timeout": 240,
  "prompt": "You are a plan checker running as a PreToolUse hook. The pending tool call is this JSON: $ARGUMENTS\nIf tool_input.file_path does not end with \"PLAN.md\", answer ok=true and stop.\nOtherwise read the file .checker/plan-rules.md inside the project directory given by \"cwd\" and check tool_input.content against every rule in it.\nIf any rule is broken, answer ok=false with reason starting with \"PLAN CHECK:\" and saying which rule is broken and exactly what to add. If every rule holds, answer ok=true." }
```

Sesión: `env -u CLAUDECODE claude -p --model haiku --setting-sources project --permission-mode acceptEdits --max-budget-usd 0.50 --output-format stream-json --verbose --debug-file …`. El prompt pide escribir `PLAN.md` sin leer archivos y, si la escritura se bloquea, corregir según la razón.

Se ejecutó dos veces (`run1`, `run2`) en `scratchpad/spikes-work/issue-4/`, nunca en un repo real.

## Hallazgos para el diseño (#19, #22)

- Formato de la razón: el texto que llega al modelo empieza por el prefijo fijo `PreToolUse:<Tool> hook error: Agent hook condition was not met: ` y sigue con el `reason` literal. El orquestador lo trata como error de herramienta y reintenta. Conviene que el prompt de `plan-check` empiece su razón con una marca propia (aquí `PLAN CHECK:`).
- `ok:true` también trae `reason`, y el arnés lo ignora.
- El agent del hook lee archivos del proyecto con `Read`, usando el `cwd` de `$ARGUMENTS`. Tiene también `Bash`: en run2 lo usó una vez, sin diálogo de permiso, y el log no registra el comando. No es de solo lectura por construcción, así que el prompt del `plan-check` debe limitarlo a leer.
- La latencia varía mucho, de 5.6 a 20.9 s por invocación. `timeout: 240` deja margen amplio.
- El hook vuelve a correr en cada intento, así que cada corrección paga otra invocación de opus. Hay que filtrar en el prompt (o con `if`) para que solo corra sobre lo que importa. En este spike filtraba por `PLAN.md` dentro del prompt, y ese filtro también cuesta una invocación.

## Qué no quedó comprobado

- **Matcher `ExitPlanMode`.** En `claude -p`, `ExitPlanMode` está deshabilitado. En el laboratorio previo (`cc-lab/run2.hooks.log`, plan mode), el modelo respondió: "I couldn't call ExitPlanMode. The tool is disabled for this session". Por eso se usó `Write`, que el issue admite. Queda pendiente del spike 0.1 (#3), que necesita sesión interactiva, confirmar que un hook `agent` en `PreToolUse` de `ExitPlanMode` se comporta igual. Si no, #19 usa la opción B.
- **`/cost` interactivo:** no se usó, porque no hay sesiones interactivas en este spike. Se midió con `total_cost_usd` y `modelUsage` del JSON de `-p`.
- **Fallos del hook:** el binario contiene los mensajes `Agent hook did not complete within 50 turns`, `Agent hook did not return structured output` y `Agent hook error:`. No se provocaron, así que no se sabe si un fallo bloquea o deja pasar la herramienta. Tampoco se probó qué pasa al agotar `timeout`.
- **Solo dos muestras.** Las dos fueron coherentes: mismo bloqueo, misma corrección, mismo paso.

## Reproducir

```

```

Requiere `claude` autenticado, `jq` y `git`. Cuesta unos $0.06–0.09 y tiene un tope de $0.50 (`--max-budget-usd`). Deja `stream.jsonl`, `debug.log`, `hooks.log` y el proyecto en `proj/`, e imprime el resumen.
